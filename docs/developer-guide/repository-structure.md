## Workspace layout

The [pnpm workspace](../../pnpm-workspace.yaml) has two applications and five internal packages, plus the root tool/orchestration package. Package exports, rather than arbitrary deep imports, are the starting public interface. Tests sometimes import a concrete source file to exercise a specific boundary; that does not turn every helper into a stable integration API.

```text
apps/
  web/                  Next.js App Router pages, API routes, client workspaces
  worker/               Queue probes and durable native financial projection
packages/
  contracts/            Public Zod DTOs, OpenAPI generation and typed client
  domain/               Framework-independent financial/review kernels
  database/             Drizzle schema, scoped transactions, SQL migrations
  server/               Authenticated application services and API adapters
  ui/                   Shared presentational React primitives
scripts/                Local/runtime, migration, release, operations, benchmarks
tests/
  unit/                 Pure contracts/kernel/security/tooling tests
  ui/                   jsdom component interaction tests
  integration/          Real isolated PostgreSQL/service/worker tests
  e2e/                  Playwright application/browser journeys
docs/                   Canonical design, task, financial and evidence references
```

Private `.env`, `.private/`, `work/`, generated runtime output, browser traces and recovery artifacts are not source documentation or public fixtures. Follow [ignore rules](../../.gitignore), [documentation standards](../documentation-standards.md) and [test isolation](testing.md). Never publish a dump, archive, source statement or credential just because a local command produced it under the checkout.
