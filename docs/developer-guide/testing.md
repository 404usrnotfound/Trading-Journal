## Preconditions and isolation

Run every command below from the **repository root**, containing `package.json`, with Node **24.19.0**, pinned pnpm **10.34.6** through Corepack and the complete frozen dependency installation. Use [local development](local-development.md), [installation](../getting-started/installation.md) and [configuration](../getting-started/configuration.md) for setup rather than copying another installation recipe here. The [root manifest](../../package.json) is the command authority.

Unit/UI checks need installed source dependencies and writable temporary/cache locations. PostgreSQL tests additionally require a deliberately disposable PostgreSQL **17** instance and four private bindings: `TEST_DATABASE_URL`, `TEST_APP_DATABASE_URL`, `TEST_AUTH_DATABASE_URL` and `TEST_JOB_DATABASE_URL`. The [guard](../../scripts/environment.ts) requires the same normalized host/port/database target, a database name ending `_test`, well-formed authenticated connection URLs and separation from every configured development target. The guard does not make an existing user's similarly named database disposable. Already-set process bindings override repository `.env`; inspect intended targets privately without printing URLs/passwords.

> **Warning:** Integration/browser/migration/recovery tooling creates schemas, provisions roles and writes or removes test records. Some fixture teardown uses privileged database operations within its uniquely scoped disposable data. Never run it against production, shared user data or a development database you need to retain. Do not copy fixture teardown into application or incident code, disable the isolation guard or rename a user database to make it eligible.

Browser checks also require a completed web build, Chromium/system libraries and an unused loopback test port. Build and test paths must never inherit production credentials. Managed sandbox/socket restrictions can block a CLI or child process; record that as **Blocked** until the intended authorized execution environment works. Do not weaken application security or network/TLS verification as a test workaround.

### Browser setup and behavior

The configured browser installation command, also used by [CI](../../.github/workflows/ci.yml), is:

```bash
corepack pnpm exec playwright install --with-deps chromium
```

This downloads browser tooling and can install operating-system libraries; it needs the platform's authorized network/installation access and is not a read-only application probe. A supported existing executable can be selected with `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`; that is a tool setting, not certification of every browser build. See [configuration](../getting-started/configuration.md) for tooling bindings and source-reviewed precedence.

The [Playwright configuration](../../playwright.config.ts) defaults `E2E_PORT` to **3002**, uses a distinct `http://localhost:<port>` origin, one worker, zero retries and 45-second test timeouts. Its owned `start:web` process runs against test role bindings with `NODE_ENV=test`; it never reuses an existing server. Global setup migrates the test instance and bootstraps a synthetic owner. [Per-journey owners](../../tests/e2e/owner-fixture.ts) prevent unrelated scenarios from sharing identity throttling. Do not supply real user credentials to make a scenario pass.

Playwright retains a trace on failure and screenshots only on failure; HTML output is under `playwright-report/`, with scenario artifacts under `test-results/`. These files can contain cookies, request bodies, financial/source data and private media. Keep them restricted and review any shared derivative. The configured seven-day CI failure-artifact retention is not a general log or backup policy. Selected axe/theme/viewport checks do not establish complete accessibility or all-browser conformance.

## Financial and import test design

Canonical arithmetic/availability definitions remain in [financial metrics](../financial-metrics.md), [portfolio accounting](../portfolio-accounting.md) and [analytics definitions](../analytics-definitions.md). The [domain guide](domain-and-financial-model.md) explains developer invariants. A calculation change should include independent stated inputs and expected outputs at the pure-domain boundary, then persisted service/API evidence for the affected scope.

Cover the relevant combinations: decimal strings beyond binary-float precision; fractional/partial entries and exits; remaining principal versus net basis; fee/rebate partition and conservation; zero versus missing costs; actual conversion versus historical/current translation; missing/stale/inverse/future FX and marks; microsecond ordering/offsets; corrections/revisions and historical replay; multiple accounts/legs/portfolios; native/manual/supplied boundaries; R eligibility and completed-campaign samples. Assert reasons/known subtotals when a result is unavailable, not a fabricated zero. Compare all intended cash, quantities, costs and source references after rejected/retried commands, including rollback/idempotency and absence of duplicate side effects.

Use [independent financial fixtures](../../tests/unit/financial-independent-fixtures.test.ts), [campaign integration](../../tests/integration/financial-correctness-campaign.test.ts), [report FX scope](../../tests/integration/report-fx-scope.test.ts) and [analytics fixtures](../../tests/integration/analytics-independent-fixtures.test.ts) as patterns. Property tests supplement fixed financial examples; preserve a reported failing seed/shrink path when available. Do not replace a financial oracle with a snapshot updated from the same faulty engine.

Import changes need parser/schema tests and service/transaction tests: UTF-8/BOM, quoted/multiline CSV, limits, headers/control data, decimal grouping and DST/offsets, reserved/deep metadata, complete dependency groups, stable identities, duplicate/correction classification, preview revisions, acknowledgements, cash variance and atomic rejection. Representative files are [parser tests](../../tests/unit/imports.test.ts), [file boundary](../../tests/unit/import-file.test.ts), [metadata safety](../../tests/unit/imports-safety.test.ts), [persisted imports](../../tests/integration/imports.test.ts) and [import safety](../../tests/integration/imports-safety.test.ts). Add an actual UI journey when a changed control/confirmation matters; a named broker catalog record does not create a live integration or adapter.

## Security and architecture checks

Test authentication, current membership/roles, Origin/CSRF, same/foreign-workspace references, private media, bounded input, safe error/log serialization and runtime privilege boundaries separately from economic calculations. Relevant sources include [security unit tests](../../tests/unit/server-security.test.ts), [credentials](../../tests/unit/server-credentials.test.ts), [logging](../../tests/unit/server-logging.test.ts), [auth integration](../../tests/integration/auth.test.ts), [database integration](../../tests/integration/database.test.ts), [portable recovery isolation](../../tests/integration/portability.test.ts) and [browser security](../../tests/e2e/browser-security.spec.ts).

The [ESLint boundary rule](../../eslint.config.mjs) rejects server/Node infrastructure imports from client code and transport/framework/infrastructure dependencies from the pure domain. Static boundaries do not replace runtime authorization or negative SQL tests. Never expose raw SQL, secret-bearing errors, session state or financial payloads to make a failing assertion easier to inspect.

| `corepack pnpm verify`                 | API drift → format → lint → types → `test` → build. Requires disposable PostgreSQL; **does not** include advisory audit, Playwright, release, HTTPS or recovery checks.                                                              |

| `corepack pnpm --silent release:check` | After fresh build, checks full source/artifact/native dependency closure and emits JSON. It does not attest stale-output provenance, production startup, financial correctness or current advisory safety.                           |

| `corepack pnpm ops:recovery-drill`     | State-changing owned PostgreSQL/media backup/restore rehearsal; use only its [documented prerequisites](../backup-and-recovery.md#reproducible-local-drill), never a live incident target.                                           |

The [CI workflow](../../.github/workflows/ci.yml) runs on pushes and pull requests using Ubuntu 24.04 and a unique Compose project. It installs the frozen graph, audits advisories **before database setup**, applies/checks migrations and restricted access, runs `verify` with its configured HTTPS origin, then release/HTTPS/recovery checks, Chromium installation and browser tests. It stops its databases in an always-run cleanup step and retains browser failure evidence when configured. There is no hosted deployment job in this workflow. A declared job and an older passing result do not establish a successful run for your commit; the current advisory failure must remain visible.

Coverage uses the configured V8 provider when requested by tooling; this repository does not establish a percentage acceptance threshold through that configuration. Judge evidence by the affected invariants/scenarios and complete selections. Record commit, versions, command, target isolation, result/counts, failures and unrun scope in the review.
