## Implementation and safety boundaries

The web application uses Next App Router/server and client components, transport DTOs in contracts, service composition in the server package, pure financial kernels in domain, and PostgreSQL models/constraints/RLS in database. A separate worker handles health probes and narrow generation-safe native cash/quantity snapshots. Imports and bounded reports execute synchronously; no live broker/feed/AI service, S3 adapter or universal advanced-asset lifecycle engine is delivered. The diagrams and extension instructions preserve those distinctions.

Use synthetic workspaces and explicitly disposable test databases. Do not change ledger facts, migration hashes, source identities, archive checksums, RLS, CSRF, TLS or safe reporting bounds to make a test pass. New financial behavior requires independent expectations and explicit units/currencies/time/revision/cost/availability checks. Source changes that add metadata or a stored number do not automatically add validated economics.

**Current gates:** the [Checkpoint 5 dependency audit](../operations/verification.md#dependency-audit-failure) reported seven advisories, including two critical, and dependencies remain unchanged. [FA-04](../final-audit.md) remains open for production capacity. A passing local typecheck/test/build is not a clean advisory report, production deployment or all-browser/capacity certification.

## API documentation generation

This checkpoint corrects documentation-generator drift and regenerates OpenAPI/client declarations; it does not change runtime handlers, behavioral Zod schemas, financial calculations or database migrations. The reviewed surface is **154 web operations across 119 paths**, plus **2 private worker health GETs**. Per-operation reference pages include method/route/purpose, authentication/authorization, parameters/body/validation, response/error schemas and fictional request/response examples.

The [API generation workflow](api-reference.md#regenerate-the-reference) keeps DTO schemas in their existing source owner and uses a source-reviewed transport-policy inventory for guards not expressible in JSON Schema. Examples are schema-checked specimens, not live captures or preseeded trading data. [Verification](verification.md) records projected-schema versus source-Zod checks, representative real API tests and every unverified workflow. Checkpoint 7 is not started.
