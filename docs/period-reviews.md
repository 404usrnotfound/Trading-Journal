# Standalone period reviews and reusable templates

Open **Period reviews** to prepare a session or retain a daily, end-of-session, weekly, monthly or custom review without creating a fictitious trade. Each record has explicit start-inclusive/end-exclusive instants, an IANA timezone, notes, goals, recurring mistakes, emotion labels and improvement actions. Weekly presets use a Monday start. Custom periods retain the entered boundaries. Existing boundaries do not change when display preferences change.

Valid drafts autosave after a short idle period. An incomplete draft stays local and navigation is guarded until it is saved or explicitly discarded. Finalization publishes an immutable version and checks required template answers. Reopening creates a new draft version; it does not edit the finalized snapshot. Permanent review URLs, paginated version history, version actor/time and change reasons retain the review context. Concurrent changes return a conflict, preserve local text and require explicit reload. A lost save response pauses editing and retains the exact idempotent command for retry before any new edit.

Templates define named text, yes/no and exact-decimal fields, optional help and required-before-finalization flags. Publishing a change appends another complete template version. A review pins its exact template version and answer definitions; later template changes cannot reinterpret existing answers. An explicitly recorded **No** satisfies a required yes/no field, while an unanswered field does not. Archiving prevents new selection while preserving existing pinned reviews. Template publication uses the same retained-command behavior after an unknown result.

Source links select existing trades and immutable strategy versions from paginated, searchable workspace catalogs. Links are optional: a review can stand alone. The database enforces same-workspace references. Selecting a period does not infer that every trade in that interval was reviewed or linked.

The deterministic summary counts the explicitly linked trades by status, recorded post-trade review coverage, linked journal mistake labels, review goals and open improvement actions. A mistake contributes at most once per linked trade. The summary retains the financial source revision, capture time and each linked trade's current status/latest journal revision identifier. It reports recorded observations; it does not infer causes, emotional quality or financial performance. Review periods and optional trade links remain separate facts. Summary reads use one repeatable-read snapshot. Summaries are generated on request rather than saved as claims that remain current after later journal edits.

Template/review identities, immutable versions, commands and relational source links use PostgreSQL persistence, forced workspace RLS and scoped foreign keys. Viewers can read; editor/owner mutations require an authenticated mutation session, CSRF proof and idempotency key. Retries return the same committed version, while changed content with the same key conflicts. Review writes do not advance the financial revision or change ledger, risk, inventory or analytics results.

Definitions are bounded to 128 KiB, 100 trade and strategy links, 50 configurable template fields, and bounded text/list lengths. Review lists support server-side title search, kind/status filters and pagination; template and history reads are paginated. Portable archives include all seven period-review tables so template pins, answers, histories and source links survive restore.

Verification covers schemas and exact time boundaries, required typed answers, independent summaries, draft/final history, idempotent retries, concurrent version conflicts, tenant references, viewer/CSRF restrictions, populated archive restore and the rendered editing/template/uncertain-save workflows. See `tests/unit/period-reviews.test.ts`, `tests/integration/period-reviews.test.ts` and `tests/ui/period-reviews.test.tsx`. These checks support remediation review; this document does not change the final audit's resolution status.
