# Release audit remediation

Date: 24 October 2026. This record supplements the original evidence in [final-audit.md](final-audit.md). Changes are verified on branch `work`; they are not deployed.

The original audit established no P0. The targeted regressions below verify P1, P2 and P3 changes in that priority order. FA-04 remains open for production capacity acceptance. Passing smaller cases does not establish its million-fill or concurrent-reader budgets.

## Verification and integrity boundaries

PostgreSQL tests use disposable databases with regular migrations and restricted application, authentication and queue roles. Published migrations0000–0008 remain unchanged; additive migrations0009–0016 bring the schema to 17. Tests retain monetary conservation, append-only history, tenant/RLS, CSRF, idempotency and source-revision checks.

Portable restore preserves the existing financial-command integrity trigger. Historical commands are checked sequentially against their original revision, audit and outbox evidence; final foreign-key, monetary and replay checks run before commit. Restore does not grant historical users access to the new workspace. Queue credentials receive four narrow dispatch functions rather than raw tenant-table access. Private saved views remain per-member and are excluded from workspace archives.

Final complete lint/type/unit/integration/browser/build results are recorded in the final audit after execution. Earlier checkpoints passed 533 PostgreSQL tests and 891 unit/property/UI tests. An intermediate integration run found an obsolete assertion rejecting signed manual futures; it was replaced with signed-source preservation, continued unsupported automatic valuation and native-negative rejection assertions, then the22-test asset-class suite passed. An intermediate browser run exposed missing reconciliation transport registration, unnecessary campaign calculations during source lookup, transient button contrast during theme changes and shared-fixture login exhaustion. The route/reference fixes, immediate button colors and independent browser owners address those demonstrated failures; final browser results supersede that checkpoint.

For reproduction, configure the isolated `TEST_*` database bindings and browser environment as described in [README](../README.md). Run `corepack pnpm api:check`, `corepack pnpm format:check`, `corepack pnpm lint`, `corepack pnpm typecheck`, `corepack pnpm test:unit`, `corepack pnpm test:integration`, `corepack pnpm build` and then `corepack pnpm test:e2e`. The disposable validation container and its private bindings were removed after the successful final runs; test source and tracked results remain.
